# Expected assets on a coordinated Hauntware release.
#
# The release workflow's checksum/publish job downloads every asset
# attached to the draft release and requires ONE downloaded match per
# entry below before it computes SHA256SUMS or flips the release
# public — the rehearsal floor: a silently missing product build can
# never certify. Entries are shell glob patterns matched against the
# asset file names; the .deb entries keep Debian's versioned filename
# convention, hence the glob.
#
# Asset names are product-prefixed, so Planchette, Séance (app and
# sync server), Poltergeist and Klabautermann files can never collide on
# the single shared release. scripts/check-workflows.sh verifies that every
# asset glob the release legs attach is represented here — keep the
# manifest and the workflow's `files:` lists in step.
#
# The Android APK names are also a contract with every installed build:
# the apps' in-app update downloads seance-android.apk and
# poltergeist-android.apk by name (their tests read this file). Renaming
# one strands installed Android builds on their version.
#
# Desktop bundles are unsigned (macOS: ad-hoc); first launch needs the
# usual unidentified-developer step. iOS IPAs are unsigned and must be
# re-signed to sideload. There is no linux-arm64 client: Flutter
# publishes no linux-arm64 host artifacts.
